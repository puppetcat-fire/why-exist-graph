# 审计产物说明

这批文件是 2026-11-06 对 why-exist-graph **2.92.0** 做的一次行为契约审计的产物。
审计之后的修复进展记录在 `REPORT.md` 的进度表里；本文件说明每类产物的状态与用法。

## 这批东西回答什么问题

不是「代码写得怎么样」，而是：**它的实现里，哪些部分能安全原地改、哪些该重写、
哪些必须冻结**。方法先提取「对外可观察的行为承诺」，再拿证据（测试 / 文档 / 实测）
对账，而不是逐行读实现。

## 怎么用它

- **想知道当时发现了什么**：读 `REPORT.md`，再看对应切片的 `NN-*.md`。
- **想核对某条结论是否还成立**：契约卡里的证据是 `文件:行号`，行号会随代码变化漂移。
  以 `REPORT.md` 的进度表为准，或按卡里的描述重新验证一遍。
- **想重跑探针**：多数探针把 2.92.0 的行为写死了。3.x 之后有修复（例如 `retract` 的
  返回字段变了、覆盖公式的分母变了、`scope_ids` 改成排序输出），直接跑会失败——
  它们是**证据**，不是回归测试。要回归请看 `tests/`。
- **想重做一次完整审计**：`aggregate.py` 只做汇总；16 个切片的提取过程没有脚本化，
  当时是用 16 路并行子代理做的，每片的范围与必答问题记录在对应 `NN-*.md` 的开头。

## 一句话

这是**一次审计的快照 + 一份持续更新的进度表**，不是可以反复消费的工具。要判断当前
状态，看 `REPORT.md` 的进度表、`CHANGELOG.md`，以及 `python tools/preflight.py` 的输出。
